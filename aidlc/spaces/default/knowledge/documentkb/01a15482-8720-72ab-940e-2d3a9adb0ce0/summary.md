SupportDesk AI project requirements (trainee assessment). Build an ASP.NET Core Web API (C#, controllers) for support-ticket management with EF Core + SQLite, Swagger, unit tests, and an AI provider (hosted LLM or Ollama, chosen by trainer; a clearly identified mock is allowed for development). A reliable, explainable MVP matters more than feature count; the trainee must explain the controller -> service -> database/AI flow in a code walkthrough.

Functional requirements: FR-01 POST /api/tickets (title, description, validated lengths); FR-02 GET /api/tickets with optional status/priority/category filters; FR-03 GET /api/tickets/{id} (404 if missing); FR-04 PUT /api/tickets/{id}; FR-05 PATCH /api/tickets/{id}/status (Open, InProgress, Resolved, Closed; reject others); FR-06 POST /api/tickets/{id}/analyze returns category, priority, sentiment, summary, suggestedAction, persisted only after validation; FR-07 POST /api/tickets/{id}/draft-reply returns a draft for human review, never sent automatically; FR-08 GET /api/dashboard/summary (total, open, high-priority, resolved counts); FR-09 understandable errors for validation, missing records, AI timeouts, provider errors and malformed AI output, without secrets or stack traces; FR-10 AI credentials from environment variables or user secrets.

Data model: Ticket with Id, Title, Description, Status enum, Priority enum (Low, Medium, High, Critical), nullable Category and Sentiment, nullable AiSummary and SuggestedAction, CreatedAt/UpdatedAt in UTC. AI text must never bypass validation for status or priority. Provide an EF Core migration or DB init steps.

Technical expectations: thin controllers, logic in services, DI, an IAiTicketService abstraction, async I/O with CancellationToken, request/response DTOs, secrets out of Git with a placeholder config example, no real personal data sent to AI, model output treated as untrusted input, AI timeout, core ticket operations must work without the AI provider. Tests for key business rules and AI-output validation.

Out of scope: fine-tuning, RAG/vector DBs, multi-agent workflows, production deployment, full auth, polished frontend. Suggested 5-day plan (CRUD -> validation/services -> AI -> dashboard/tests -> README/demo). Done means: builds from README, data persists across restarts, 4xx/404 behaviour, typed AI validation, draft-only replies, no credentials in repo, README with setup/config/migrations/examples/limitations, pushed to GitHub with meaningful commits.
